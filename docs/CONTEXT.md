# 미리내 마켓

서비스의 목적·사용자 흐름·핵심 용어를 이해하고 관련 문서를 찾기 위한 맥락의 진입점이다. 상세 업무 계약은 Spec, 결정 이유는 ADR, 구현·검증·병합 상태와 다음 작업은 PLAN에서 관리한다.

## 서비스 목적과 범위

구매자는 전통시장 방문 전에 한 시장의 매장별 상품과 포장 가격을 비교하고, 온라인으로 예약 구매한 상품을 당일 매장에서 직접 수령한다. 판매자는 이미 확보한 물량 중 온라인으로 판매할 수량을 등록하고 확정 주문의 상품을 수령용으로 준비한다.

포트폴리오·학습용 서비스이며 결제는 실제 금액을 청구하지 않는 모의 결제다. 도매 매입·납품, 현장 POS·실물 재고 자동 연동은 범위 밖이다. 동작하는 사용자 흐름을 확보한 뒤 판매자 주문 집계의 정확성과 성능을 측정하는 것이 개발 목표다. 상세 범위는 [Spec의 목적과 범위](../SPEC.md)를 따른다.

## 핵심 사용자 흐름

- 판매자: 본인 매장 확인 → 상품 등록 → 오늘 판매할 상품·포장 가격·온라인 수량과 공통 주문 마감·수령 시간 작성 → 변경 사항 적용. 상품 등록과 실제 판매 공개는 구분한다.
- 구매자: 시장 선택·상품 검색 → 상품 상세 확인 → 장바구니 담기·수량과 조건 확인 → 통합 모의 결제 → 별도 주문 내역에서 매장별 상품·수령 정보 확인.
- 수령·취소·판매 실패·환불은 매장 주문을 기준으로 다룬다. 이 후속 흐름의 제품 계약은 [Spec](../SPEC.md), 구현 여부와 미정 항목은 [PLAN](../PLAN.md)을 확인한다.

장바구니와 주문 내역은 별도 화면이다. 장바구니에 담는 것만으로 재고를 선점하지 않으며 서버에서 결제 확정에 먼저 성공한 요청이 구매한다. 결과를 받지 못한 결제는 실패로 단정하지 않고 같은 요청의 결과를 확인한다. 상세 정상·실패 계약은 [Spec의 Phase 4](../SPEC.md), 선점 제외와 동시성 처리의 결정 이유는 [ADR-007](ADR.md)을 따른다.

## 개발 방향과 문서 안내

기능과 사용자 흐름을 먼저 완성하고 시각 디자인은 이후 전체 화면에 맞춰 개선한다. 화면 분리·이동 흐름과 업무 결과 안내는 기능 구현 때 확정한다. 구체적인 남은 작업과 완료 상태는 [PLAN](../PLAN.md)에 유지한다.

| 필요한 맥락 | 참조 |
|---|---|
| 서비스가 어떻게 동작해야 하는가 | [SPEC.md](../SPEC.md)의 관련 기능·수용 기준 |
| 왜 이 구조·정책을 선택했는가 | [docs/ADR.md](ADR.md)의 관련 결정과 대체 관계 |
| 현재 목표·구현 상태·다음 행동은 무엇인가 | [PLAN.md](../PLAN.md)의 현재 상태와 최신 결과 |
| 어떻게 실행·사용·검증하는가 | [README.md](../README.md)의 관련 절차 |
| 개발·검증·리뷰에서 무엇을 지켜야 하는가 | [AGENTS.md](../AGENTS.md) |

관련 문서를 작업에 맞춰 선택한다. 현재 브랜치의 구현·배포 상태는 사용자 흐름 설명만으로 판단하지 않고 PLAN과 실제 Git·실행 환경을 확인한다.

## Language

**시장 (Market)**: 여러 매장이 속한 장소이며 구매자가 검색·구매할 범위를 선택하는 단위다.

**매장 (Store)**: 한 판매자가 상품을 제공하고 구매자가 직접 방문해 수령하는 점포다.

**구매자 (Buyer)**: 시장을 선택해 상품을 예약 구매하고 매장에서 수령하는 사용자다.

**판매자 (Seller)**: 본인 매장의 상품·당일 판매 조건을 관리하고 확정 주문의 상품을 제공하는 사용자다.

**판매 단위 (Sale Unit)**: 구매 수량 한 개에 해당하는 상품 구성이다. 500g 봉지나 12개들이 박스 등이 해당한다.

**날짜별 판매 제안 (Daily Offer)**: 특정 수령일에 판매할 상품의 판매 단위·가격·온라인 판매 수량과 판매 활성 여부다.

**온라인 판매 가능 수량 (Online Available Quantity)**: 판매자가 확보한 물량 중 새 온라인 주문에 판매할 수 있는 잔여 판매 단위의 개수다. 매장 전체 실물 재고나 이미 확정된 주문 수량과 구분한다.

**장바구니 (Cart)**: 구매자가 결제 전에 상품·구매 수량·확인한 판매 조건을 모아 둔 목록이다. 확정 주문이나 재고 선점을 뜻하지 않는다.

**결제 요청 (Checkout Request)**: 장바구니의 상품을 통합 결제하기 위해 제출한 처리 요청이다. 처리 중(PENDING)·확정(CONFIRMED)·실패(FAILED)를 구분하며 처리 중이거나 실패한 요청을 확정 주문으로 부르지 않는다.

**모의 결제 (Mock Payment)**: 실제 금액을 청구하지 않고 결제 성공·실패·지연·응답 유실을 재현하는 구매 처리다.

**통합 주문 (Checkout)**: 한 시장의 하나 이상의 매장 상품을 묶어 결제가 확정된 구매 단위다. 매장별 상품·수량·결제 당시 조건을 포함한다.
_Avoid_: 매장 주문과 구분하지 않은 주문

**매장 주문 (Store Order)**: 통합 주문 중 한 매장이 제공하는 상품의 묶음이며 수령과 전체 취소를 판단하는 단위다.

**판매 실패 (Fulfillment Failure)**: 판매자가 약속한 상품을 제공하지 못하는 상황이다.
_Avoid_: 구매자 미수령

**미수령 (No Show)**: 구매자가 수령 마감까지 유효한 매장 주문을 찾아가지 않은 상황이다.
_Avoid_: 판매 실패

**판매 중단 (Sale Suspension)**: 특정 수령일의 판매만 비활성화한다. 상품·판매 기록과 저장한 가격·수량을 보존한다. 상품 삭제 및 수량 0인 품절과 구분한다.

**일괄 판매 적용 (Batch Sales Apply)**: 매장 공통 시간과 수정한 상품들의 가격·수량·판매 여부를 모두 저장하거나 전부 미적용하는 작업이다. 작성 중 상태와 구매자에게 공개된 상태를 구분한다.
